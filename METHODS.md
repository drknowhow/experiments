# Methods

The practices every experiment here follows, and the ones a particular
experiment adds. When an experiment departs from one, its DESIGN.md says so.

## Design before data

Each experiment starts with a `DESIGN.md`: the question, the subjects, the
items, how each item is scored and the hypotheses. It is written before any
model is called. Anything settled later is added under a dated heading that
says whether model output informed it.

For `haiku-delegation-bench`, the first experiment, this repository did not
exist yet when the design was written, so the git history cannot show that
the design came first. From the next experiment on, `DESIGN.md` is committed
before the first model call.

## Items and gold

Gold answers come from something other than a model wherever possible:
executing the code, computing from the generator's own events, the commit
that produced a diff, a grep over a pinned checkout. Items are generated by
scripts in the experiment's `gen/`, and the build fails if any gold check
fails.

**Gold check.** An item that every model gets wrong, including the ceiling
model, is re-examined for bad gold before results are written. Every change
made that way is logged in RESULTS.md with the item id and the reason.

## Grading

Graders are deterministic code, never a model. Each grader has a self-test
that builds a perfect reply and a wrong reply from every item's gold and
checks that they score 1 and below 1. The self-test runs before any grading.

A reply that does not contain the answer format the item asked for is a
**format failure** and scores 0. A call that fails (timeout, CLI error)
also scores 0 but is counted separately. A timeout under the production
time limit is treated as the model's result. Other call failures are rerun
once.

## Repetition and uncertainty

The subject model and the baseline run 3 reps of every item; the ceiling
model runs 1. Results report the mean over reps and the spread between them.

- Per-category gaps between two models: paired bootstrap over items, 10,000
  resamples, fixed seed (`20261017`), 95% percentile interval.
- Proportions (accuracy on a labelled set): Wilson 95% interval.
- Paired right/wrong comparisons on the same items: exact McNemar test.

## Isolation of CLI calls

Experiments that measure Claude through the `claude` CLI use
`_lib/claude_runner.py`, which starts every call fresh
(`--no-session-persistence`) and replaces the default system prompt with
the experiment's own (`--system-prompt`). Its three modes copy the flags a
coding agent's delegation tool uses:

- `single`: `--safe-mode --tools ""`. No CLAUDE.md, skills, plugins,
  hooks, output styles, MCP servers or tools.
- `scout`: `--restricted --tools Read,Grep,Glob`. User, project and local
  settings are ignored and the file tools are confined to the working
  directory.
- `worker`: as `scout`, plus Edit and Write allowed only on the item's
  write set, with edits elsewhere refused.

All three also pass `--strict-mcp-config`, and the runner removes the
environment variables that would make the child think it is nested in a
parent session or inherit the parent's thinking budget.

We checked this on Claude Code 2.1.302. A control call without these flags
quoted the machine owner's global CLAUDE.md back; calls in all three modes
did not. One piece of context still gets through: the CLI adds the
machine's current date ("Today's date is ...") to every call. Items that
depend on a date state it in the prompt, and results note any item where
the injected date changed an answer.

## Cost

Calls go through the `claude` CLI, which reports a list-price cost per call
(`total_cost_usd`). Our calls bill against a subscription, so the dollar
figures are a relative measure of load between models, not money spent.
Prompt caching changes them too, so compare ratios, not absolute values.

## Private data

Some questions can only be answered on private data, such as our own email.
Those inputs stay on the machine they live on and are passed to the script by
path. Raw per-row outputs go to a directory outside this repository (the
scripts refuse a path inside it). Only aggregates are committed: counts,
accuracy, per-class support, precision and recall. Classes with fewer than 15
labelled rows are reported but not interpreted.

## Routing rule (haiku-delegation-bench)

Fixed before the main grading. For each category, with Haiku's and Sonnet's
mean scores:

| Condition | Route |
|---|---|
| Haiku ≥ 95% of Sonnet, and Haiku invents no more often than Sonnet | Haiku |
| Haiku ≥ 85% of Sonnet (or ≥ 95% but with more inventions) | Haiku, with a check on its output |
| Haiku < 85% of Sonnet | Sonnet |

An **invention** is a confident answer where the right answer was "not in
the input": a non-null field where gold is null, an answer to an
unanswerable question, or a file path where gold is `NOT_FOUND`.
